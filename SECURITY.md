# Publication and privacy boundaries

This public repository is a curated showcase, not the application source or an operational reporting channel.

## What belongs here

- High-level purpose, product descriptions and research limitations.
- Reviewed community-interface screenshots without private reports or accounts.
- Presentation materials that do not expose operational access or configuration.

## What must remain private

Application source and technical implementation details are maintained separately at the owner's request. Never add private keys, service-account files, tokens, administrator invitations, recovery codes, user reports, precise private locations, database dumps, server logs, private endpoints or unreviewed exports here. Do not upload APKs or application bundles as a workaround: distributed client software can be inspected.

## Reporting an exposure

Do not post credentials, exploit details or personal information in public issues, comments or pull requests. Contact the owner through an independently verified private channel. If you do not have one, request a private contact method without including sensitive details. No monitored emergency or guaranteed-response service is implied.

## Important limits

Changing repository visibility does not recall earlier public downloads, forks, caches or clones. Removing a file in a later commit does not erase it from history. If a credential was exposed, revoke or rotate it first, then assess history and cached copies. No claim is made here that every historical commit has been audited.

Reference: [GitHub guidance on removing sensitive data](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository).
